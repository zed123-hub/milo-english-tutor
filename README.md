# Milo · 开口，就是开始

Milo 是面向中国学习者的个人英语语音导师。本地运行，一次安装服务一个人，无注册、无登录。配置自己的 API Key 后，导师通过交流认识你，主动带你听英语、说英语，不需要填写入学问卷或手动选择课程。

**当前版本：0.5.4 开发预览。** 这一版仍在持续验证，不代表所有 Realtime 服务商和真实麦克风环境均已稳定。导师设计为只说英语并使用一个英文声线；中文仅用于可选字幕和教学摘要。没有文字作答入口。

## 本地启动

安装 [Node.js](https://nodejs.org/) 22.13 或以上版本，然后在源码目录运行：

```sh
npm ci
npm run build
npm start
```

打开 **http://localhost:3000/**，配置模型并允许麦克风。macOS 可以双击 `启动 Milo.command`。重启软件后重新填写 Key，学习记忆会保留。

开发模式为 `npm run dev`，页面支持热更新；修改服务端代码后需要重启。可以通过环境变量 `PORT` 更改端口。服务仅监听本机 `127.0.0.1`。

## 两种模型职责

设置分为「实时交流」和「课后分析与教学安排」。两者可使用不同服务商、模型和 Key。

| 交流方式            | 对话模型                             | 听和说                     |
| ------------------- | ------------------------------------ | -------------------------- |
| 自然实时语音        | OpenAI / Qwen3.5 Omni / GLM Realtime | 原生流式音频，支持开口打断 |
| 语音服务 + 自选模型 | 自选文本模型                         | OpenAI 转写、语音合成      |
| 系统语音 + 自选模型 | 自选文本模型                         | 浏览器听写、系统英文朗读   |

文本对话与课后分析支持 DeepSeek、GLM、GPT、Qwen、MiniMax 和兼容 API。在 DeepSeek 模型选择中可选 V4.1 Flash（API 模型名 `deepseek-flash`）；原有预设和已保存模型名称保持不变，名称也可手动编辑。Qwen 地址应与 Key 地域一致，也支持百炼业务空间专用域名。文本预设按 [DeepSeek 官方接口](https://api-docs.deepseek.com/api/create-chat-completion/)、[Qwen 兼容接口](https://www.alibabacloud.com/help/en/model-studio/compatibility-of-openai-with-dashscope) 和 [MiniMax 兼容接口](https://platform.minimax.io/docs/api-reference/text-openai-api) 接入。

分析 Key 留空时，仅在服务商和地址相同的情况下共用对话 Key。OpenAI 声音服务和 OpenAI 文本模型也可共用同一账号的 Key。切换服务地址会清除该角色旧 Key。千问和 GLM 的实时 Key 单独填写，不会沿用 OpenAI Key；课后分析仍在下方独立配置。

挂断先保存整段交流，再在后台逐条分析学生表现，更新画像、证据、摘要和下一次教学安排。学生说完一轮后，分析模型还可并行检查一处明显的英语用法问题，在页面给出轻量提示；检查不会让实时导师停下来等，也不会记为已掌握。后台分析期间仍可开始新对话。「成长足迹」显示整理进度；失败不自动反复调用付费接口，可在修正配置后点击「继续整理」。重启、迁移后可从已保存进度接续。

### 原生实时语音配置

| 服务   | 默认模型                      | 连接方式                         |
| ------ | ----------------------------- | -------------------------------- |
| OpenAI | `gpt-realtime-2.1-mini`       | 后端协商 WebRTC                  |
| 千问   | `qwen3.5-omni-flash-realtime` | 本机代理 WebSocket；也支持 Plus  |
| 智谱   | `glm-realtime-air`            | 本机代理 WebSocket；也支持 Flash |

在模型设置选择「自然实时语音」及服务商。千问可选北京或新加坡，也可填写百炼专属 WebSocket 地址；Key 必须属于同一地域。这里的千问适配支持带工具调用的 Qwen3.5 系列。

浏览器通过短期、单次票据连接本机代理，服务商 Key 只用于后端请求头。音频以 100 ms PCM 帧发送；千问输入 16 kHz，GLM 输入 24 kHz，输出均使用 24 kHz。打断会取消生成并清空本地播放；Qwen/GLM 不发送未获确认支持的服务端历史截断事件。

浏览器短暂卡顿后补发的录音按音频时长限制，控制事件单独限流。浏览器和本机代理在上传变慢时按顺序缓存声音与提交事件；短暂停顿不会因固定等待时间或缓冲峰值直接结束会话。缓冲达到内存上限、连接实际断开时会报错并停止，断开后清空未发送的缓存。

三家服务分别管理连接、配置确认、回应和取消状态。OpenAI 的教学策略更新仅发送 instructions 和会话类型，不重发模型、音色或音频配置；Qwen 使用 server_vad，普通学生轮次由服务端提交并创建回复。GLM 每次更新教学提示都会发送完整会话配置，保留音频格式与接话设置，关闭重复开场，并等待服务确认后继续请求回应。

实时会话采用短上下文：固定提示词、工具说明及随附的画像、教学安排与最近交流都限制长度；动态策略不再重复注入聊天正文，也不会因为时间戳变化而重发。OpenAI 在初次连接设置 4,000 个指令后历史 token 的裁剪阈值，触发时保留约 60%。Qwen 和 GLM 在完整语音回复与转写结束后重建上游会话，仅带短文本承接，浏览器播放与本地学习会话保持连续，不重复开场，也不额外调用摘要模型。Qwen 默认在 4 个学生轮次、60 秒上传音频或单次输入达到 4,000 token 时请求压缩；GLM 对应为 6 轮、90 秒或 4,000 token，均至少完成两轮并等待安全衔接时机。这些是历史管理阈值，不是费用硬上限。新连接可能带来短暂等待，不能保证固定节省比例。完整学习记录仍保存在本机。

工具参数晚于回答完成事件到达时，仍会回传结果；取消或重复的工具调用不会再次执行。工具参数按服务商 schema 验证，错误参数不会修改学习数据。模型收到固定错误结果后最多自动修正一次；同一轮再次失败时保持监听，等待学生继续开口。

GLM 使用本机声音活动检测：开口后流式上传，停顿约 1.2 秒自动提交，收到服务端提交确认后才请求回答；短促噪声不触发对话，连续长回答会分段提交，等你停顿再回复。迟到确认不会在你继续说话或暂停后触发旧回复。这样保留导师工具，同时避开已有人报告的 GLM 自动检测与工具组合问题。[上游问题记录](https://github.com/MetaGLM/glm-realtime-sdk/issues/21) 尚无维护者结论；本机检测也会受麦克风音量、回声和环境噪声影响。

老师说完之前不等待中文字幕、学生转写或课后分析。OpenAI 使用 800 ms 停顿检测；等待声音约 9 秒会提示，25 秒仍未响应或播放超过 45 秒时继续保留会话，供你等待或手动暂停。OpenAI 暂时断线会等待恢复，确认连接失败才结束。持续无声时，导师提醒后仍可能主动暂停。手动暂停会立刻停麦克风与声音，并给迟到转写最多约 1.8 秒收尾。网络及服务商本身的生成延迟仍会影响体感；网络故障不会触发反复重连或重试付费语音。

## 怎样带着学生说

- 导师的固定提示词、工具说明和静默提醒使用英文；中文学习记录作为参考数据保留，中文字幕与页面教学摘要仍可使用中文。
- 开始对话时从最近的交流或可用记忆自然接话，没有固定开场白。学生没有话题时，导师主动贡献具体观察、观点或生活情境中的新进展，让学生有内容可以自然接话。
- 提问是可选的，导师不会连续用问句收尾；先接住学生的意思，再用自己的观点或具体细节推进同一个生活情境。不要求学生选场景或做跟读练习；只有明确求助或理解受阻时才提供必要的语言帮助。
- 日常对话中使用熟悉表达，并逐步加入少量新词、句型或交际动作。
- 学生连贯表达观点时，当次交流立即减少提示、放开句长和话题深度，接住内容并自然展开；不会因此写入“已掌握”。转写规则排除提示后回答和复制老师示范，模型也收到直接根据听到的表现调整的约束。
- 学生说 “too easy”“too hard”“slow down” 时调整本次互动；长期难度仍依据多次实际表现。
- 多次、跨日期、不同表达的独立使用，才触发小幅难度调整；连续需要帮助时降低负担。调整涉及句长、回答长度、词汇、语法、提示量和话题。
- 到期表达自然出现在后续交流中，并提供日常、兴趣、点餐、购物、出行等生活情境建议。
- 沉默时先等待，再用贴近当前交流的一句评论或新细节继续话题，不重复催问、不自动转为示范练习；持续没有回应会暂停麦克风。必要纠正融入自然回应，每次只处理一个有用的点。

这些是已实现的教学约束和保守规则，模型执行效果仍取决于所选模型和实际交流。它们不等于已经验证了长期教学成效。

## 成长、字幕与教学思路

「成长足迹」保留真实开口次数、语音活动时长、全部对话和课后摘要。听过老师示范、在帮助下说过、独立说过、隔天使用、跨场景使用分别记录。示范必须来自已播放老师原话，学生表达必须能在对应转写中找到；模型捏造的短语不会写入成果。

对话区有两个辅助按钮：

- **字幕**：英文 → 中英 → 关闭。只显示老师的话。英文随语音逐词出现；中英整组出现。字幕位于底部，长内容上移，顶部渐隐。暂停或打断冻结进度。
- **教学思路**：查看可公开的教学意图、当前安排、难度调整，以及本轮并行检查发现的明显用法问题；有提示时，对话页也会短暂显示小卡片。打开面板后语音仍可继续，不展示隐藏思维链。

系统语音优先使用真实 `boundary` 事件同步；没有词边界时使用时间估算。语音 API 按音频播放进度估算；Realtime 按音频与转写事件估算，尚不是精确逐词对齐。Realtime 中英字幕按需调用已配置的分析模型翻译老师原话，可能有短暂延迟和额外费用；翻译最多等待约 16 秒，等待和失败时仍显示老师的英文原话，不打断交流。并行用法检查也使用已配置的分析模型，会产生额外的短文本请求；没有确定把握时不显示纠错卡片。

## 本机记忆与迁移

在「记忆与迁移」查看有学生原话依据的画像和导师安排，导出整份 JSON，再在另一台部署了 Milo 的设备上导入并重新配置 Key。

本机数据保存在 `.milo-data/learning.sqlite`，非秘密模型偏好保存在 `.milo-data/preferences.json`。对话历史、画像、学习证据、教学安排和分析进度都进入迁移包；**API Key 和原始录音不进入迁移包，软件不保存原始录音。** 模型每次只接收必要的近期上下文，完整记录仍保留在本机。

导入前可预览数量。确认导入后完整替换当前数据，并保留一个可恢复的导入前快照。旧请求不能覆盖新导入的数据。支持 schema 3 学习备份升级到 schema 4；V2 文字学情作为历史资料保留，不转换成口语成果。早期托管版需要在那里手动导出资料。

单个迁移包上限 20 MB。超限会明确报错，不删减学习记录；关闭软件后完整复制 `.milo-data` 可作数据库备份。

## 隐私与声音边界

Key 仅在当前本机服务进程的内存中保存，不返回页面、不写入数据库或偏好文件、不进入导师提示词。关闭服务会清除 Key。声音与必要的对话会发给你选定的服务商，可能产生 API 费用；本地存储并不意味着模型离线运行。

学习数据库与导出包是明文个人资料，应妥善保管设备及备份。本机接口检查 Host、Origin、专用请求头；文本接口只允许受支持域名的 HTTPS，实时转发只允许白名单 WSS 域名；禁止重定向。其他可信接口域名可以通过 `ALLOWED_API_HOSTS` 配置。无账号的个人服务不适合直接暴露到公网。

实时连接错误区分配置、声音格式、权限、额度、上传积压、控制事件过频、会话失效和连接中断。每个服务商的最近一次连接诊断保存在本机 `.milo-data/realtime-diagnostics/`，文件权限为 0600：仅含连接状态、配置接受/拒绝、音频计数、语音与响应事件、工具参数拒绝、上下文重建次数和安全错误类别。另保留服务商报告的输入/输出、文本/音频与缓存 token 数值及字段覆盖次数；缺失字段表示未知，最多保存最近 64 条用量样本，不据此推算金额。OpenAI 的 RTP 包计数与 WebSocket 的 PCM 帧计数分开。错误字段路径、客户端事件类型及校验规则使用白名单，不保存 Key、对话正文、录音、原始错误或事件 ID；诊断不进入学习资料迁移备份。WebSocket 缓冲峰值等辅助数据仍仅保留在进程内存中。

系统语音效果受浏览器和操作系统影响，浏览器听写可能联网。中英混合、口音和噪声会影响识别；原生音频和转写/合成也取决于服务商及账号权限。标准模式在发声前检查英文内容，Realtime 则在非英文转写到达后中断输出；流式音频可能先于转写到达。

## 开源开发与验证

源代码采用 [MIT License](LICENSE)。

`main` 保存已公开的预览快照；`codex/development` 用于继续开发。请从开发分支提交后续修改，验证通过后再合入 `main`。仓库不会包含 API Key、本机学习数据、诊断记录或旧托管站点配置。

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run package:source
```

运行 `npm run package:source` 后，源码包输出到本机 `releases/`；该目录不随 Git 提交。

入口为 `local/main.tsx` → `components/coach-app.tsx`；`local/server.ts` 提供本机接口，`local/repository.ts` 适配 SQLite，`lib/coach/` 包含教学、证据、迁移、字幕和语音逻辑。参见 [本地架构](docs/local-architecture.md)。仓库保留早期 Sites/Vinext 代码供历史回归；带 `:sites` 的命令不是当前本机应用入口。

测试使用隔离数据库、模拟模型、语音事件与本机 WebSocket 对端，覆盖并发写入、分析续跑、资料迁移、密钥隔离、GLM 完整配置和工具事件乱序，不消耗真实 API 额度。自动化检查不等同于真实账号和麦克风端到端验证。时长是语音活动估计，转写不能提供可信音素评分；本版不声明发音分数、CEFR 等级或固定课时学会英语。

语音协议依据：[Qwen Realtime](https://www.alibabacloud.com/help/zh/model-studio/realtime)、[Qwen 工具调用](https://www.alibabacloud.com/help/zh/model-studio/qwen-function-calling)、[GLM Realtime](https://docs.bigmodel.cn/cn/guide/models/sound-and-video/glm-realtime)、[OpenAI Realtime WebRTC](https://developers.openai.com/api/docs/guides/realtime-webrtc)、[语音转写](https://developers.openai.com/api/docs/guides/speech-to-text)、[语音合成](https://developers.openai.com/api/docs/guides/text-to-speech)、[Web Speech 词边界事件](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/boundary_event)。
